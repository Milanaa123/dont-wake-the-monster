## 1. Как получить Studio, если у тебя только телефон

У Roblox Studio **нет версии для Android**. Нужен один компьютер с Windows или macOS, но это не обязательно должен быть **твой** компьютер.

Самый простой вариант: один раз воспользоваться разрешённым компьютером с Windows (например, домашним компьютером знакомого, с его согласия) или арендованным **полноценным облачным рабочим столом Windows** с графическим интерфейсом и поддержкой 3D. Не путай такой рабочий стол с сервером Linux / SSH / «VPS без экрана».

Для облачного Windows нужны доступ с телефона через приложение удалённого рабочего стола или браузер и возможность запускать настоящие Windows-программы. Roblox рекомендует Windows 11 и 8 ГБ оперативной памяти. Проверить поддержку Roblox Studio у облачного провайдера нужно **до оплаты**.

У нас уже был экспериментальный Windows GitHub Actions runner: Studio установилась, но запустить Play без авторизации не удалось. Runner — временная автоматическая среда, а не заменитель постоянного управляемого рабочего стола.

Документация: https://create.roblox.com/docs/studio/setup

## 2. Открыть игру в Roblox Studio

1. На Windows войди в Roblox Studio **самостоятельно** в своём новом Roblox-аккаунте. **Не передавай никому пароль, cookies и 2FA-коды**. При использовании облачного ПК входи только через свой защищённый удалённый рабочий стол.
2. Открой успешный запуск [GitHub Actions](https://github.com/Milanaa123/dont-wake-the-monster/actions/runs/44483461546) и скачай в разделе **Artifacts** архив `roblox-place`. Распакуй ZIP.
3. В Studio выбери **File → Open from File** и укажи `dont-wake-the-monster.rbxlx` из архива.
4. Нажми **Play (F5)**. Проверь, что появляются остров, Giggles, питомец, кнопки сада и корма.
5. Испытай поглаживание (удерживать), переноску, поиск семян и пробуждение монстра. Следи за ошибками в **View → Output**. Сохрани скриншоты ошибок, не секреты аккаунта.
6. Для настоящей записи используй программу захвата экрана, например OBS Studio, в собственной Windows-сессии. Сними 1–2 минуты фактического Play; **не называй рендер или симуляцию записью**.

Внимание: это исходная сборка для проверки, а не подтверждённый работающий релиз. Некоторые ошибки могут обнаружиться только при реальном Play.

## 3. Привязать игру к своему Roblox-аккаунту

1. Пока загруженный `.rbxlx` открыт в Studio, выбери **File → Publish / Publish to Roblox**.
2. Создай **новую игру** с именем `Don't Wake the Monster!`, описанием и подходящим жанром. Сохрани на своём аккаунте, но **оставь доступ приватным** для тестов.
3. В [Creator Dashboard](https://create.roblox.com/dashboard/creations) открой эту игру → **Places** → стартовый Place.
4. Скопируй числовой **Place ID** из URL. Он **не является паролем**. Его можно прислать в чат для проверки инструкций.

Официальная последовательность: https://create.roblox.com/docs/production/publishing/publish-games-and-places

## 4. Потом обновлять игру из GitHub без Studio

Только **после** появления Place ID:

1. В [Roblox Creator Dashboard → API Keys](https://create.roblox.com/dashboard/credentials?activeTab=ApiKeysTab) создай отдельный ключ с правами **Assets API — Read + Write**. Ограничь его одной нашей игрой. Если указанная прямая ссылка изменилась, открой Creator Dashboard и найди раздел **API Keys**.
2. В **GitHub → Settings → Secrets and variables → Actions → New repository secret** сохрани ключ **под именем `ROBLOX_API_KEY`**. Сам ключ **не копируй в чат, коммиты или Issues**.
3. Открой [Upload Roblox place (manual)](https://github.com/Milanaa123/dont-wake-the-monster/actions/workflows/upload-roblox.yml). Запусти **Run workflow**. Введи свой Place ID и выбери **Saved**.
4. Режим **Saved** загружает черновую версию. Он **не** делает её публичной. После проверки можно выбрать **Published**, что обновляет версию места; доступ самой игры остаётся отдельной настройкой.
5. Дальше все обновления кода могут собираться и загружаться из GitHub, без постоянного открытия Studio. **Игровые тесты** всё равно требуют настоящей Roblox-сессии.

Официальный API: https://create.roblox.com/docs/cloud/guides/usage-place-publishing

## 5. Подключить собственную музыку и эффекты

У нас уже созданы 19 оригинальных WAV: спокойная музыка, погоня, лес, питомцы, смешные звуки.
Сначала загрузи их через Roblox Creator Dashboard как звуковые ассеты и проверь модерацию/разрешения. Затем заполни числовые ID в `src/shared/AudioConfig.luau` и `Config.PurrSoundId` в `src/shared/Config.luau`.

**Пока ID равны нулю, звуки внутри Roblox не слышны**, несмотря на то что WAV существуют в GitHub. См. [AUDIO.md](AUDIO.md).

## 6. Что ещё нельзя считать готовым

- Сохранять прогресс в реальном Roblox DataStore нужно проверить в тестовом опыте. Для коммерческого релиза нужны распределённые блокировки сессий данных.
- Проверить мобильный интерфейс и FPS, анимацию переноски и 2+ одновременных игрока.
- Платёжные товары за Robux не активировать до надёжной серверной выдачи по `ProcessReceipt` и проверки правил Roblox.
- Проверить требования к возрасту/публикации перед открытием публичного доступа; расходы сейчас необязательны.

## Если в мобильном приложении виден раздел Build

Roblox начал вводить **Build** — мобильное создание простых 2D/2.5D игр. Он доступен не всем регионам и **не заменяет** открытие нашего текущего 3D `.rbxlx` проекта. Не генерируй новую отдельную игру в Build, рассчитывая, что туда автоматически попадёт код из GitHub.

Документация Build: https://create.roblox.com/docs/ai/build

**Самое первое действие:** получить доступ к полноценному Windows-компьютеру (своему/одолженному/удалённому), где можно лично войти в Roblox Studio. Далее всё делается по пунктам выше.
